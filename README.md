# AI Travel Planner & Ticket Booking Assistant

A Flask-based travel planning and ticket booking project using **Groq AI** and **MySQL**.

## Main features
- User registration and login
- AI travel planning
- Starting location and destination
- Travel date, days and number of travelers
- Budget / Standard / Luxury travel style
- Approximate complete-trip budget in INR
- Date-aware budget estimation
- Same-search budget reuse for consistent repeated results
- Places to visit and day-by-day itinerary
- Date-specific ticket planning options
- Multi-passenger seat selection
- Booking confirmation and booking history
- Booking cancellation
- Admin dashboard

## Important behavior
The planner stores the generated result in MySQL. Repeating the same search with the same user, source, destination, travel date, days, travelers, travel style and interests reuses the saved result, so the budget remains the same. A different travel date or other search input can produce a different estimate.

Ticket searches are also stored with their exact travel date. Repeating the same route/date/transport search for the same user reuses the stored date-specific options.

Ticket options generated by Groq in this project are planning estimates, not verified live transport inventory. Always verify the final price, schedule and seat availability before completing a real-world purchase.

## Setup
1. Install Python 3.
2. Install MySQL and make sure the MySQL service is running.
3. Create a `.env` file from `.env.example`.
4. Add your own Groq API key and MySQL settings.
5. Install dependencies:

```powershell
pip install -r requirements.txt
```

6. Run:

```powershell
python app.py
```

Open `http://127.0.0.1:5000`.

The Flask application automatically creates the MySQL database and required tables.


## Live pricing
The planner uses Groq for itinerary generation, but it does not treat Groq as a live price source.
When authorized Amadeus credentials are configured, the planner attempts live round-trip flight and hotel offers and combines them with AI estimates for food, local transport and activities.
If live provider access is unavailable, the application clearly labels the affected values as estimates.
IRCTC train information/booking requires an authorized IRCTC integration; this project does not pretend that an unauthenticated public endpoint is live inventory.

Important: `https://test.api.amadeus.com` is a test/sandbox endpoint. Do not call sandbox results live production prices. For production live pricing, use the production/enterprise endpoint and credentials supplied by your authorized Amadeus access.


## Shared ticket inventory

Ticket searches are now shared by exact source, destination, travel date and transport type. A repeated search does not create a new inventory for another user. Seats are stored in `booked_seats` with a unique `(ticket_result_id, seat)` constraint, so two users cannot book the same seat for the same ticket option. Cancellation releases the seats.

The app uses a MySQL transaction and row locking during booking to protect the shared inventory from concurrent bookings. MySQL documents `SELECT ... FOR UPDATE` as a locking read that blocks conflicting transactions until commit/rollback.
